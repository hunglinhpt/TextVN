## EN
- **ARM-M1 — Universal gate for every macOS binary**: every Mach-O inside `.app`/`.pkg` must carry BOTH `arm64` + `x86_64` slices; any missing slice ⇒ print the offending file list and `exit 1` (prevents a repeat of OpenKey #189 — a single-arch binary slipping into a release ⇒ red).
- **Single source (G22)**: the gate functions live at the top of `scripts/build-macos.sh` (`textvn_uni_have_both_archs`, `textvn_uni_is_macho`, `textvn_uni_archs_of`, `textvn_uni_scan_dir`); `scripts/package-macos-pkg.sh` reuses them by sourcing this file through a `[ "${BASH_SOURCE[0]}" = "$0" ] || return 0` guard (sourcing loads the functions only, never runs the build body). The old "TextVN-IM not universal" warning (covered a single binary) is removed — the gate supersedes it by scanning every Mach-O in the payload.
- **Real release order**: the gate runs AFTER bundles are assembled, BEFORE `codesign`/notarize (build-macos.sh step 5b) and BEFORE `pkgbuild`/`productbuild` (package-macos-pkg.sh step 3) — no signing/packaging time is wasted on a broken build.
- **Mach-O detection without `file`**: reads the first 4 bytes via `od` (MH_MAGIC/MH_CIGAM 32/64 + FAT_MAGIC/CIGAM 64) — available on macOS as well as Git Bash on Windows; arch probing prefers `lipo -archs` (overridable via `TEXTVN_UNI_LIPO` for tests), falls back to parsing `file -b` output. Unprobeable ⇒ treated as FAIL (fail-closed).
- **Host-only builds now fail at the right place**: if one of the two rust targets / swift archs is missing, the completed build is rejected by the gate before signing, with guidance (`rustup target add aarch64-apple-darwin x86_64-apple-darwin` + `swift build --arch arm64 --arch x86_64`) — a release must never contain a single-architecture binary.
